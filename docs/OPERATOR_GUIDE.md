# 🎛️ Data Assistant · OPERATOR_GUIDE

**Проект:** ai-data-assistant
**Дата:** 2026-08-12

Руководство оператора: как менять поведение приложения без программирования, пересборки и рестарта контейнера.

---

## 🔐 1. Доступ к админке

1. Задайте `ADMIN_TOKEN` в `.env` (bootstrap, требует рестарта при первой установке).
2. Откройте `http://<host>:<port>/admin`.
3. Браузер запросит логин/пароль HTTP Basic:
   - пользователь: `admin`
   - пароль: значение `ADMIN_TOKEN`

Если `ADMIN_TOKEN` не задан — `/admin` отключён (403).

![Админка: общий вид](screenshots/ADA_admin_overview.png)

*Общий вид `/admin`: двухколоночный layout — слева редактор промпта, справа Runtime-конфиг и реестры, сверху дашборд статистики.*

## ⚙️ 2. Операторские параметры

Все параметры ниже меняются в runtime — **применяются на следующем запросе без рестарта**. Единственный источник истины — `storage/config.json`; начальные значения сеются из хардкоженных умолчаний при первом старте (в `.env` этих параметров нет).

| Параметр | Что делает | Пример |
|----------|------------|--------|
| **Провайдер** (пресет) | Выбор провайдера модели — заполняет endpoint, модель, имя, structured_output | OpenAI / GigaChat / YandexGPT / Свой |
| **Модель** | Имя модели (для Yandex — URI с `<folder_id>`) | `gpt-5-mini`, `GigaChat-Max` |
| **Endpoint провайдера** | OpenAI-совместимый base_url | `https://api.openai.com/v1` |
| **Имя провайдера** | Имя провайдера в контенте; пусто = нейтрально | «OpenAI», «GigaChat» или пусто |
| **Structured output** | Строгий контракт ответа (Вкл/Выкл) | Вкл для OpenAI/«Свой»; Выкл для GigaChat/YandexGPT |
| **Специализация ассистента** | Роль/профиль в системном промпте | «финансовый аналитик», «эксперт по ритейлу» |
| **Температура модели** | Креативность 0–2; отправляется только если явно задана (не сброшена) | `0.3`, `0.7` |
| **Seed модели** | Воспроизводимость; пусто = не отправляется | `42` |
| **Сообщений истории** | Сколько последних сообщений передаётся в модель | `8` |
| **Лимит размера файла** | Максимум размера загрузки | `10MB`, `5MB` |
| **Yandex folder_id** | Каталог Yandex Cloud (только для пресета YandexGPT) | `b1g...` |

> **Тултипы.** Наведите мышь на название любого параметра — появится подробный
> комментарий о его смысле и ограничениях.

> **Портабельность температуры/seed.** Температура и seed — opt-in: после чистого
> старта они отсутствуют в `config.json`, и `has()` возвращает `False`, поэтому
> они **не отправляются** в запрос. Температура отправляется только если оператор
> **явно задал** её в `/admin` (и перестаёт — после «Сбросить»). Это критично:
> некоторые модели (например `gpt-5-mini`) поддерживают только умолчательное
> значение температуры и отвергают любое иное. Если модель не принимает `seed`,
> оставьте поле пустым. Невалидные значения (не число) дают явную ошибку в карточке.

![Админка: температура и seed](screenshots/ADA_admin_temp_seed.png)

*Карточки параметров с тултипами: температура (0–2) и seed (целое / пусто = не отправляется).*

## 🛠️ 3. Как изменить параметр

1. Откройте `/admin`.
2. В карточке параметра введите новое значение (или выберите из списка для bool).
3. Нажмите **«Сохранить»**.
4. Появится подтверждение «→ <новое значение>. Применится на следующем запросе без рестарта.»
5. Следующий запрос пользователя использует новое значение.

Кнопка **«Сбросить»** удаляет ключ из `config.json`: параметр возвращается к хардкоженному умолчанию. Для opt-in параметров (температура/seed/имя провайдера) сброс = «не задавать» — параметр перестаёт отправляться в запрос.

## 🧪 3.1. Тест провайдера

После смены модели/endpoint/провайдера проверьте, что провайдер отвечает:

1. В секции **«Провайдер»** нажмите **«Тест провайдера»**.
2. Статус покажет либо «✓ Провайдер отвечает. Модель …, латентность N мс», либо «✕ Провайдер недоступен» с текстом ошибки.

Пинг отправляет минимальный запрос (`ping`) к текущим `base_url` + модель **без** `temperature`, `seed`, `response_format` и `max_tokens` — портабельно для моделей, не принимающих эти параметры. Для GigaChat пинг идёт через OAuth-адаптер. Тест **не записывается** в статистику использования.

![Админка: смена модели и тест провайдера](screenshots/ADA_admin_model_swap.png)

*«Тест провайдера» подтверждает сменённую модель и показывает латентность до чат-запроса.*

## 📊 3.2. Статистика использования

В верхней части `/admin` — dashboard «Статистика использования»:

- **Запросов** / **Ошибок** — счётчики обращений к модели.
- **Токенов всего** / **Промпт-токены** / **Комплит-токены** — расход токенов (если провайдер возвращает `usage`; иначе считается только запрос).
- **Последний запрос** / **Последняя ошибка** — временная метка и текст последней ошибки.

Счётчики хранятся в `storage/usage.json` (персистентно через volume) и обновляются при перезагрузке `/admin`. Используется для контроля расходов LLM. Диагностический «Тест провайдера» и локальные действия (анализ/графики без модели) в статистику не попадают.

![Админка: статистика использования](screenshots/ADA_admin_usage.png)

*Дашборд статистики: запросы, ошибки, токены (prompt/completion/total), время последнего запроса и ошибки.*

## 🔌 4. Смена провайдера модели

В `/admin` есть секция **«Провайдер»** с пресетами: **OpenAI**, **GigaChat**,
**YandexGPT**, **Свой**. Клик по чипу пресета одним действием заполняет
endpoint, модель, имя провайдера и флаг structured_output. После пресета поля
можно править и по отдельности.

![Админка: пресеты провайдера](screenshots/ADA_admin_provider_presets.png)

*Чипы пресетов (OpenAI / GigaChat / YandexGPT / «Свой») и автозаполненные поля после выбора.*

**OpenAI** (эталон, работает сразу):
1. Кликните чип **OpenAI**.
2. Убедитесь, что в `.env` задан `OPENAI_API_KEY`.
3. Нажмите **«Тест провайдера»**.

**GigaChat (Сбер)**:
1. В `.env` задайте `GIGACHAT_AUTH_KEY` (authorization key Сбер) и перезапустите
   контейнер. Опционально `GIGACHAT_CA_BUNDLE` — путь к CA-bundle Минцифры (без
   него проверка TLS отключается, что приемлемо для dev/демо).
2. Кликните чип **GigaChat** — пресет заполнит endpoint
   (`https://gigachat.devices.sberbank.ru/api/v1`), модель (`GigaChat-Max`) и
   выключит structured_output.
3. Нажмите **«Тест провайдера»**. OAuth-обмен access-токена идёт под капотом
   (per-request, refresh скрыт) — ручного обновления токена не требуется.

**YandexGPT**:
1. В `.env` в `OPENAI_API_KEY` подставьте API-ключ Yandex (он используется как
   Bearer). Перезапустите контейнер.
2. Кликните чип **YandexGPT**.
3. В поле **Yandex folder_id** укажите идентификатор каталога Yandex Cloud
   (без него YandexGPT не работает — folder_id подставляется в URI модели и в
   заголовок `x-folder-id`).
4. Нажмите **«Тест провайдера»**.

**Свой (любой OpenAI-совместимый endpoint)**:
1. Кликните чип **Свой**.
2. Заполните **Endpoint** и **Модель** вручную.
3. В `.env` задайте `OPENAI_API_KEY` (ключ вашего провайдера как Bearer).
4. **Structured output** — оставьте Вкл, если провайдер поддерживает
   `json_schema` strict, иначе Выкл.

> Секреты (`OPENAI_API_KEY`, `GIGACHAT_AUTH_KEY`) меняются только в `.env` с
> рестартом — они не входят в операторские параметры. GigaChat и YandexGPT не
> поддерживают `json_schema` strict — для них пресет выключает structured_output,
> и ответ модели разбирается устойчивым парсером.

Все остальные настройки применяются на следующем запросе без рестарта.

## 📝 5. Правка промпта

Системный промпт — файл `prompts/v1/system.md`. Это **единственный источник
истины** текста промпта (не config.json). В `/admin` есть отдельная карточка
«Системный промпт» с многострочным редактором:

- Доступны переменные `{{specialization}}` (подставляется специализация —
  операторский параметр) и `{{provider_attribution}}` (« от <имя провайдера>»
  либо пусто).
- Нажмите **«Сохранить промпт»** — файл `prompts/v1/system.md` перезаписывается
  напрямую. Применяется на следующем запросе (mtime-кеш), без рестарта.
- Можно также править файл напрямую (файловым менеджером на сервере) —
  эффект тот же.

![Админка: редактор промпта](screenshots/ADA_admin_prompt_edit.png)

*Карточка «Системный промпт»: многострочный редактор файла `prompts/v1/system.md` с тултипом-источником.*

> **Production.** Каталог `prompts/` монтируется volume (`./prompts:/app/prompts`),
> поэтому правки переживают рестарт/пересборку. Каталог лежит в репозитории —
> `git pull` может перезаписать операторские правки промпта; коммитьте их
> обратно в репозиторий или резервируйте файл перед обновлением.

## 🗂️ 6. Прямое редактирование config.json

Операторские параметры хранятся в `storage/config.json` — это их единственный
источник истины. Правка файла напрямую (файловым менеджером на сервере)
применяется в runtime — mtime-кеш подхватывает изменение на следующем запросе.

При первом старте файл создаётся автоматически: `ensure_initialized` сеет
хардкоженные умолчания (`DEFAULTS`) для always-active параметров
(`SEEDED_KEYS`, включая `provider`). Opt-in параметры (`provider_name`,
`openai_temperature`, `openai_seed`, `yandex_folder_id`) **не сеются** — они
отсутствуют, пока оператор их не задаст (это и управляет портабельностью, см. §2).

Пример файла после применения пресета GigaChat и правки оператора:

```json
{
  "assistant_specialization": "эксперт по ритейлу",
  "provider": "gigachat",
  "openai_model": "GigaChat-Max",
  "openai_base_url": "https://gigachat.devices.sberbank.ru/api/v1",
  "provider_name": "GigaChat",
  "structured_output": false,
  "openai_max_history_messages": 8,
  "max_file_size": "10MB",
  "openai_temperature": 0.3
}
```

Здесь `provider=gigachat` и 4 поля провайдера заполнены пресетом; `openai_temperature`
добавлен оператором (будет отправляться); `openai_seed` и `yandex_folder_id`
отсутствуют. Секреты (`OPENAI_API_KEY`, `GIGACHAT_AUTH_KEY`, `ADMIN_TOKEN`) сюда
**не писать** — только в `.env`.

> `temperature` и `seed` отправляются в запрос модели только если ключ
> присутствует в `config.json` (для seed — и не равен `null`). `provider_name`
> отсутствует = нейтральная атрибуция. `yandex_folder_id` учитывается только при
> `provider=yandex`. Удалите ключ (или «Сбросьте» в `/admin`), чтобы провайдер
> использовал своё умолчание.

## 🧩 6.1. Реестры агента (типы графиков и действия)

Секция `/admin` → «Реестры агента» редактирует поведение агента без кода и
рестарта. Единый источник истины — `storage/registries.json` (сеется при первом
старте из `app/services/registries.py`, правится кнопкой «Сохранить реестры»).

**Действия** (preview / analyze / generate_chart / generate_report /
save_summary) фиксированы кодом — у каждого исполнитель в `ChatService`.
Редактируются только лейбл и подсказка (то, что видит модель и пользователь).

**Типы графиков — данные.** Для каждого типа: лейбл, подсказка модели, промпт
чипа чата и рецепт рендера:

| Поле рецепта | Значения | Описание |
|--------------|----------|----------|
| `kind` | `histogram`, `categorical`, `timeline` | исполнитель рендера |
| `style` | `bar`, `pie` (только categorical) | стиль categorical-графика |
| `agg` | `sum`, `mean`, `count` | агрегация по категории (пусто: pie→sum, bar→mean) |
| `x_role` / `y_role` | `dimension`, `numeric`, `datetime`, `none` | выбор осей по умолчанию из ролей колонок |
| `top_n` / `limit` / `bins` | целые | обрезка выборки / число точек / корзины гистограммы (bins пусто = авто) |

**Добавление типа графика не требует кода**: «+ добавить тип графика», ключ
(латиница/цифры/подчёркивание), рецепт одного из трёх kind'ов — после
сохранения тип появляется в чипах чата, в enum `chart_type` structured output
и в валидации плана модели на следующем запросе. **Новый тип исполнителя
(новый `kind`) требует кода** — в runtime добавляются типы поверх трёх
табличных kind'ов.

При ошибке валидации сохранение отклоняется целиком («Не сохранено — …»), файл
не изменяется. «Сбросить» возвращает кодовые дефолты (текущие runtime-правки
теряются).

### 🧪 6.1.1. Сквозной пример: добавить тип графика за 5 минут

Задача: дать агенту тип «ТОП-5 выручки по категориям» (столбцы, сортировка
по убыванию, 5 позиций).

1. Откройте `/admin` → «Реестры агента» → «+ добавить тип графика».
2. Ключ: `top5_revenue` (латиница/цифры/подчёркивание — он же станет значением
   `chart_type` в контракте модели).
3. Поля: Лейбл — `ТОП-5 выручки`; Подсказка — «топ-5 категорий по сумме показателя»;
   Промпт чипа — «Построй топ-5 категорий по выручке»;
   Рецепт: kind — `categorical`, style — `bar`, agg — `sum`, x_role — `dimension`,
   y_role — `numeric`, top_n — `5`.
4. Нажмите **«Сохранить реестры»** → статус «Реестры сохранены (N тип(ов) графиков).
   Применение — на следующем запросе…» (файл `storage/registries.json` перезаписан,
   рестарт не нужен).
5. Проверка в чате: обновите страницу — чип «ТОП-5 выручки» появился в quick-grid;
   кликните чип или попросите «топ-5 категорий по выручке» — агент вернёт план с
   `generate_chart` + `chart_type=top5_revenue`, график строится по рецепту.
6. Проверка контракта (опционально): в следующем ответе модели при
   structured-output-режиме значение `chart_type` принадлежит обновлённому enum
   (реестр — единый источник истины для схемы, чипов и валидации).

Если сохранение вернуло «Не сохранено — …» — найдите подсвеченное поле (чаще
всего ключ не в латинице или agg не из списка), исправьте и сохраните заново:
предыдущее состояние файла не менялось. Не понравился результат — «Сбросить
реестр» вернёт кодовые дефолты (учтите: сотрёт и все остальные runtime-правки
реестра).

## 🔑 6.2. Общий пароль чата (APP_PASSWORD)

По умолчанию пароль **не задан** — чат открыт всем (режим публичного демо).
Чтобы закрыть UI (чат, загрузки, `/storage`, артефакты) общим паролем:

1. На сервере в `.env` задайте `APP_PASSWORD=<ваш пароль>` (действует на всех:
   изоляции пользователей нет — модель общего демо-доступа).
2. Пересоздайте контейнер: `docker compose -f docker-compose.yml up -d
   --force-recreate` (короткое окно — это bootstrap-параметр, через админку
   не меняется).
3. Проверка: откройте сайт без cookie — попадёте на страницу «Вход» (303 на
   `/login`); после входа — cookie-сессия на 30 дней, повторный вход не нужен.

Смена пароля → **все выданные сессии инвалидируются мгновенно** (секрет
HMAC-подписи меняется). Возврат в открытый режим — очистите `APP_PASSWORD` и
пересоздайте контейнер. `/admin` паролем чата **не открывается** — остаётся за
HTTP Basic (`ADMIN_TOKEN`, §1) как второй фактор. Подробности модели —
[`SECURITY_NOTES.md`](SECURITY_NOTES.md) §4.5.

## ⚡ 6.3. Настроить агента под клиента за 10 минут

Маршрут по разделам, от чистого инстанса до настроенного демо:

1. **Провайдер** (§4) — пресет клик-чипом: OpenAI / GigaChat / YandexGPT / Свой;
   «Тест провайдера» (§3.1) подтверждает связку endpoint+модель. Секреты — в
   `.env` до этого (§7).
2. **Специализация** (§2) — роль ассистента: «финансовый аналитик», «эксперт по
   ритейлу» — попадает в системный промпт.
3. **Промпт** (§5) — при необходимости скорректируйте текст; применяется на
   следующем запросе.
4. **Реестры** (§6.1, §6.1.1) — уберите лишние типы графиков или добавьте
   доменные (по сквозному примеру выше); поправьте лейблы действий под лексику
   клиента.
5. **Статистика** (§3.2) — после первых клиентских запросов проверьте расход
   токенов и ошибки в дашборде.
6. (Опционально) Закройте доступ паролем — §6.2.

Рестарт на всех шагах, кроме правки `.env` (§7), не требуется.

## 🚫 7. Что требует рестарта (НЕ операторские параметры)

- `OPENAI_API_KEY`, `GIGACHAT_AUTH_KEY`, `GIGACHAT_CA_BUNDLE`, `ADMIN_TOKEN`, `APP_PASSWORD` — `.env` + рестарт (для `APP_PASSWORD` — см. §6.2: смена пароля инвалидирует все сессии).
- `APP_HOST`, `APP_PORT`, пути к каталогам, `RUNTIME_CONFIG_PATH` — `.env` + рестарт.
- Состав зависимостей (`requirements.txt`) — пересборка образа.
