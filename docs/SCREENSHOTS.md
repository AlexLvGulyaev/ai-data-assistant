# 🖼️ Data Assistant — галерея экранов

**Проект:** ai-data-assistant
**Дата:** 2026-08-13
**Статус:** as-built (скриншоты — human-in-the-loop)

---

## 🎯 1. Назначение

Визуальная галерея интерфейса Data Assistant. Каждый экран описан тремя
вопросами: **Что показано / Роль в системе / Почему важно**. Каталог с IMG-ID
и схемой нейминга — в [`screenshots/MEDIA_INDEX.md`](screenshots/MEDIA_INDEX.md).
Сквозные сценарии воспроизведения — в [`E2E_SCENARIOS.md`](E2E_SCENARIOS.md).

> Скриншоты делает оператор в браузере по живому демо
> `https://data-assistant.alex-n8n.site`. Файлы складываются в
> `docs/screenshots/`.

# Пользовательский контур (чат)

## 📤 2. Главная: загрузка файла — IMG-01

![Главная: загрузка файла](screenshots/ADA_home_upload.png)

- **Что показано:** главная страница с зоной загрузки файла (CSV/изображение).
- **Роль в системе:** точка входа пользователя; отсюда начинается любой сценарий.
- **Почему важно:** показывает, что система принимает файлы без установки и
  регистрации — нулевой порог входа для демонстрации заказчику.

## 📋 3. Preview CSV — IMG-02

![Preview CSV: таблица и мета](screenshots/ADA_preview_csv.png)

- **Что показано:** первые строки таблицы, мета (строки/колонки/numeric),
  кнопки действий.
- **Роль в системе:** подтверждение загрузки и стартовая точка для действий.
- **Почему важно:** оператор сразу видит, что файл распознан корректно, до
  любого вызова модели.

## 📊 4. Анализ файла — IMG-03

![Анализ: карточка статистики](screenshots/ADA_chat_analyze.png)

- **Что показано:** карточка анализа — stats-strip, инсайты, таблица
  статистик по числовым колонкам.
- **Роль в системе:** локальное действие (без LLM): метрики, NaN-профиль,
  авто-инсайты.
- **Почему важно:** ключевая ценность «посмотреть данные за секунду» без
  промпта и токенов.

## 🧩 15. Чат с GigaChat + fallback-парсер — IMG-14b

![Чат с GigaChat + fallback-парсер](screenshots/ADA_chat_gigachat_fallback.png)

- **Что показано:** шапка чата «GigaChat: GigaChat-Max» + круговая диаграмма,
  построенная через fallback-парсер (structured_output=off).
- **Роль в системе:** провайдер без `json_schema` strict — модель отвечает
  свободным текстом, парсер разбирает и исполняет действие.
- **Почему важно:** доказывает мультипровайдерность без правки кода и
  корректную атрибуцию провайдера в UI (не захардкожен «OpenAI»).

# Операторский контур (админка `/admin`)

## 🔐 15. Общий вид `/admin` — IMG-15

![Админка: общий вид](screenshots/ADA_admin_overview.png)

- **Что показано:** двухколоночный layout — слева редактор промпта, справа
  Runtime-конфиг + Реестры, сверху дашборд статистики.
- **Роль в системе:** единая консоль оператора для всех заменяемых параметров.
- **Почему важно:** демонстрирует, что система управляется без правки кода и
  рестарта.

---

## 📝 16. Редактор промпта — IMG-16

![Админка: редактор промпта](screenshots/ADA_admin_prompt_edit.png)

- **Что показано:** левая панель с текстом системного промпта и тултипом-источником.
- **Роль в системе:** файл-SOT `prompts/v1/system.md`, редактируемый из UI.
- **Почему важно:** смена промпта без деплоя — быстрая адаптация под домен
  заказчика.

---

## 🤖 17. Смена модели — IMG-17

![Админка: смена модели](screenshots/ADA_admin_model_swap.png)

- **Что показано:** поле «Модель» изменено, «Тест провайдера» подтверждает
  новую модель и латентность.
- **Роль в системе:** runtime-замена модели + диагностический пинг.
- **Почему важно:** оператор видит, что сменённая модель реально отвечает,
  до чат-запроса.

---

## 🔌 18. Пресеты провайдера — IMG-18

![Админка: пресеты провайдера](screenshots/ADA_admin_provider_presets.png)

- **Что показано:** чипы пресетов (OpenAI / GigaChat / YandexGPT / «Свой») и
  автозаполненные поля после выбора.
- **Роль в системы:** один клик — смена провайдера с подстановкой endpoint/
  модели/structured_output.
- **Почему важно:** мультипровайдерность без правки конфига — портабельность
  решения.

---

## 🌡️ 19. Температура и seed — IMG-19

![Админка: температура и seed](screenshots/ADA_admin_temp_seed.png)

- **Что показано:** поля «Температура» (0–2) и «Seed» (целое / пусто).
- **Роль в системе:** управление креативностью и воспроизводимостью модели.
- **Почему важно:** opt-in семантика (пусто = не отправляется) бережёт
  gpt-5-mini и подобные от отвергнутых запросов.

---

## 🎯 20. Специализация — IMG-20

![Админка: специализация](screenshots/ADA_admin_specialization.png)

- **Что показано:** поле «Специализация» с тултипом о плейсхолдере
  `{{specialization}}`.
- **Роль в системе:** подстановка роли в системный промпт.
- **Почему важно:** один движок — много доменов (финансы, ритейл, логистика)
  через одну строку.

---

## 🗂️ 21. Реестры агента — IMG-21

![Админка: реестры агента](screenshots/ADA_admin_registries.png)

- **Что показано:** две read-only панели — «Действия» (ACTION_TYPES) и
  «Типы графиков» (CHART_TYPES), прижатые к Runtime-конфигу.
- **Роль в системе:** функциональное ядро ассистента — что модель может
  планировать.
- **Почему важно:** оператор видит границы системы: какие действия и графики
  гарантированно поддерживаются.

---

## 📈 22. Статистика использования — IMG-22

![Админка: статистика использования](screenshots/ADA_admin_usage.png)

- **Что показано:** дашборд — запросы, ошибки, токены (prompt/completion/total),
  время последнего запроса/ошибки.
- **Роль в системы:** мониторинг расхода LLM (BUSINESS_VALUE §8).
- **Почему важно:** контроль стоимости — ключевой риск LLM-автоматизаций.

---

## 🔒 23. structured_output — IMG-23

![Админка: structured_output](screenshots/ADA_admin_structured_output.png)

- **Что показано:** переключатель structured_output в полях провайдера.
- **Роль в системе:** строгий контракт ответа (json_schema) vs fallback-парсер.
- **Почему важно:** совместимость с провайдерами без json_schema strict
  (GigaChat, YandexGPT).
